# Μάθημα 5 · Φόρμες, έλεγχος και εμφάνιση υπό συνθήκη

**Στόχοι:** να χειρίζεσαι το submit μιας φόρμας, να ελέγχεις τα δεδομένα με καθαρές συναρτήσεις
έξω από το component, και να δείχνεις στοιχεία μόνο όταν χρειάζεται.

```bash
npm run lesson 5
```

## Submit με τον τρόπο της React

Μια κανονική HTML φόρμα, όταν γίνει submit, στέλνει τα δεδομένα και **ξαναφορτώνει τη σελίδα**.
Σε μια εφαρμογή React αυτό θα έσβηνε όλο το state. Γι' αυτό:

```jsx
const handleSubmit = (event) => {
  event.preventDefault()   // σταμάτα το reload, το αναλαμβάνουμε εμείς
  …
}

<form onSubmit={handleSubmit} noValidate>
  …
  <button type="submit">Έναρξη</button>
</form>
```

Γιατί `<form>` και `onSubmit`, και όχι ένα `onClick` στο κουμπί; Γιατί έτσι το **Enter** σε
οποιοδήποτε πεδίο κάνει submit, όπως περιμένει ο χρήστης, χωρίς επιπλέον κώδικα.

Το `noValidate` κλείνει τα αυτόματα μηνύματα του browser, γιατί δείχνουμε δικά μας στα ελληνικά.

## Οι κανόνες έξω από τα components

Ο έλεγχος «κάθε παίκτης έχει όνομα, όλα τα ονόματα διαφορετικά» είναι **κανόνας του παιχνιδιού**,
όχι κομμάτι της οθόνης. Τον βάζουμε σε δικό του αρχείο, `rules.js`, ως **καθαρή συνάρτηση** (pure function):

```js
export const validatePlayers = (names) => {
  if (names.some((name) => name === '')) return { type: 'missingName' }
  const lower = names.map((name) => name.toLowerCase())
  if (new Set(lower).size !== lower.length) return { type: 'duplicateName' }
  return null
}
```

Καθαρή συνάρτηση σημαίνει:

- το αποτέλεσμα εξαρτάται **μόνο** από τα ορίσματα,
- **δεν αλλάζει** τίποτα έξω από τον εαυτό της (ούτε DOM, ούτε state, ούτε τα ορίσματα).

Κερδίζουμε τρία πράγματα: τη διαβάζεις χωρίς να ξέρεις React, την ξαναχρησιμοποιείς όπου θέλεις,
και την ελέγχεις με tests σε ένα κλάσμα του δευτερολέπτου (μάθημα 14). Στο `rules.js` θα
μαζευτούν σιγά σιγά όλοι οι κανόνες του Wizard.

Πρόσεξε ότι η συνάρτηση επιστρέφει **ένα αντικείμενο που περιγράφει το λάθος** (`{ type: 'missingName' }`),
όχι το ελληνικό κείμενο. Το κείμενο είναι δουλειά της οθόνης:

```js
const errorMessages = {
  missingName: 'Κάθε παίκτης χρειάζεται όνομα.',
  duplicateName: 'Τα ονόματα πρέπει να είναι διαφορετικά.',
}
```

Έτσι οι κανόνες δεν ξέρουν ποια γλώσσα μιλάει η εφαρμογή. Στο μάθημα 13 αυτό γίνεται η βάση για
τις μεταφράσεις.

Το `new Set(lower)` κρατάει μόνο τις μοναδικές τιμές. Αν έχει λιγότερα στοιχεία από τον πίνακα, κάποιο
όνομα επαναλαμβάνεται.

## Εμφάνιση υπό συνθήκη

Τρεις τρόποι, ανάλογα με την περίπτωση:

```jsx
{error && <p className="error">…</p>}          // δείξε το ή τίποτα

{hookRule ? 'με' : 'χωρίς'}                     // το ένα ή το άλλο

if (!started) return null                       // όλο το component ή τίποτα
```

Το `a && b` στη JavaScript δίνει `b` αν το `a` είναι «αληθές», αλλιώς το `a`. Η React δεν σχεδιάζει
τα `null`, `undefined`, `false`. **Προσοχή στο `0`**: το `{count && <p>…</p>}` με `count = 0`
σχεδιάζει ένα «0» στην οθόνη. Σε αριθμούς γράψε `{count > 0 && …}`.

## Ο κώδικας αυτού του μαθήματος

- **Submit:** το `handleSubmit` καθαρίζει τα κενά (`trim`), ελέγχει με `validatePlayers`, και είτε
  δείχνει λάθος είτε «ξεκινάει». Προς το παρόν το «ξεκινάει» απλώς γράφει μια περίληψη, γιατί το
  πραγματικό παιχνίδι χρειάζεται το επόμενο μάθημα.
- **Το λάθος σβήνει** μόλις ο χρήστης αλλάξει κάτι (`setError(null)` στα `changeName`, `changeCount`).
  Μικρή λεπτομέρεια, μεγάλη διαφορά στην αίσθηση.
- **Πρώτος dealer:** ένα controlled `<select>`. Οι τιμές των `<option>` είναι πάντα κείμενο, γι' αυτό
  το `Number(event.target.value)`. Το «Κλήρωση» διαλέγει τυχαία θέση. Αν μειωθούν οι παίκτες κάτω από
  τον επιλεγμένο dealer, επιστρέφουμε στον πρώτο.
- **`maxLength`:** τα ονόματα κόβονται στους 20 χαρακτήρες για να χωράνε στον πίνακα σκορ.
- **`<label htmlFor="first-dealer">`** συνδέει την ετικέτα με το `<select id="first-dealer">`, όταν
  δεν μπορούμε να βάλουμε το πεδίο μέσα στην ετικέτα.

## Ασκήσεις

**1. Τουλάχιστον δύο γράμματα.** Πρόσθεσε κανόνα: κάθε όνομα πρέπει να έχει τουλάχιστον 2 χαρακτήρες,
με μήνυμα «Κάθε όνομα θέλει τουλάχιστον 2 γράμματα.».

<details>
<summary>Λύση</summary>

Στο `rules.js`, μετά τον έλεγχο για κενά:

```js
if (names.some((name) => name.length < 2)) return { type: 'shortName' }
```

Στο `Setup.jsx`:

```js
const errorMessages = {
  missingName: 'Κάθε παίκτης χρειάζεται όνομα.',
  shortName: 'Κάθε όνομα θέλει τουλάχιστον 2 γράμματα.',
  duplicateName: 'Τα ονόματα πρέπει να είναι διαφορετικά.',
}
```

Ο κανόνας μπήκε στο `rules.js` και το κείμενο στο component. Ο κανόνας λέει **τι** πάει στραβά, το
component **πώς** το λέμε.

</details>

**2. Ίδια ονόματα με και χωρίς τόνο.** Σήμερα «Άννα» και «άννα» θεωρούνται ίδια, αλλά «Άννα» και «Αννα»
όχι. Κάν' τα να θεωρούνται ίδια.

<details>
<summary>Λύση</summary>

```js
// "Άννα" → "αννα": lowercase, accents removed
const simplify = (name) => name.toLowerCase().normalize('NFD').replace(/\p{Diacritic}/gu, '')

export const validatePlayers = (names) => {
  …
  const simple = names.map(simplify)
  if (new Set(simple).size !== simple.length) return { type: 'duplicateName' }
  return null
}
```

Το `normalize('NFD')` χωρίζει το «ά» σε «α» + τόνο, και το `replace` πετάει τους τόνους. Άλλαξε μόνο μία
καθαρή συνάρτηση, και το component δεν το κατάλαβε καν.

</details>

## Σύνοψη

- `<form onSubmit>` και `event.preventDefault()`: δωρεάν υποστήριξη του Enter, χωρίς reload.
- Οι κανόνες ζουν σε καθαρές συναρτήσεις (`rules.js`) και επιστρέφουν δεδομένα, όχι κείμενο.
- `&&` για «δείξε ή τίποτα», `? :` για «το ένα ή το άλλο». Προσοχή στο `0`.
