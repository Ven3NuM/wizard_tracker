# Μάθημα 4 · Λίστες, keys και controlled inputs

**Στόχοι:** να σχεδιάζεις λίστες από πίνακες με `map`, να ξέρεις γιατί θέλουν `key`, να αλλάζεις
πίνακες στο state χωρίς να τους «χαλάς», και να μην αποθηκεύεις την ίδια πληροφορία δύο φορές.

```bash
npm run lesson 4
```

## Λίστες με `map`

Το JSX είναι τιμή JavaScript, άρα ένας πίνακας από JSX σχεδιάζεται κανονικά. Το `map` μετατρέπει
έναν πίνακα δεδομένων σε πίνακα στοιχείων:

```jsx
const PLAYER_COUNTS = [3, 4, 5, 6]

{PLAYER_COUNTS.map((count) => (
  <button key={count} onClick={() => changeCount(count)}>
    {count}
  </button>
))}
```

Τα τέσσερα σχεδόν ίδια κουμπιά του μαθήματος 3 έγιναν ένα. Αν αύριο το παιχνίδι υποστηρίζει 7
παίκτες, αλλάζεις μόνο τον πίνακα.

## Το `key`

Κάθε στοιχείο μιας λίστας θέλει ένα `key`, μοναδικό ανάμεσα στα «αδέλφια» του. Με αυτό η React
καταλαβαίνει **ποιο στοιχείο είναι ποιο** όταν η λίστα αλλάζει: τι προστέθηκε, τι έφυγε, τι
μετακινήθηκε.

- Το καλύτερο key είναι ένα σταθερό id από τα δεδομένα, εδώ ο ίδιος ο αριθμός `count`.
- Ο **δείκτης** (`i`) είναι αποδεκτός μόνο όταν η λίστα δεν αναδιατάσσεται και αλλάζει μόνο στο τέλος.
  Τα πεδία ονομάτων είναι τέτοια περίπτωση: προσθέτουμε και αφαιρούμε μόνο από το τέλος, και η θέση
  «Παίκτης 2» είναι πράγματι η ταυτότητα του πεδίου.
- Αν το ξεχάσεις, η React σε προειδοποιεί στην κονσόλα.

## Μην αλλάζεις το state απευθείας (immutability)

Το state το **αντικαθιστάς**, δεν το τροποποιείς:

```jsx
names[1] = 'Άννα'      // λάθος: αλλάζει τον ίδιο πίνακα, η React δεν το καταλαβαίνει
setNames(names)        // ίδιος πίνακας → η React θεωρεί ότι δεν άλλαξε τίποτα

setNames(replaceAt(names, 1, 'Άννα'))   // σωστό: νέος πίνακας με την αλλαγή
```

Η React ελέγχει αν άλλαξε κάτι συγκρίνοντας **αναφορές** (`παλιό === νέο`), όχι περιεχόμενο. Ένας
νέος πίνακας είναι το σήμα «άλλαξα».

Γι' αυτό φτιάχνουμε τη μικρή βοηθητική συνάρτηση:

```js
const replaceAt = (values, index, value) =>
  values.map((current, i) => (i === index ? value : current))
```

Τα εργαλεία της JavaScript που δεν αλλάζουν τον αρχικό πίνακα: `map`, `filter`, `slice`,
`Array.from`, και το spread (`[...names, '']`). Αυτά που τον αλλάζουν και **δεν** τα θέλουμε στο
state: `push`, `splice`, `sort` (πάνω σε πίνακα του state), ανάθεση `names[i] = …`.

## Μία πηγή αλήθειας

Στο μάθημα 3 είχαμε `playerCount` στο state. Τώρα που υπάρχει πίνακας ονομάτων, ο αριθμός παικτών
είναι απλώς **`names.length`**. Αν κρατούσαμε και τα δύο, θα έπρεπε να θυμόμαστε να τα αλλάζουμε
μαζί, και κάποια στιγμή κάποιο θα ξεχνιόταν.

> Ό,τι μπορεί να υπολογιστεί από το υπάρχον state δεν μπαίνει στο state.

Θα ξαναδούμε αυτόν τον κανόνα στο μάθημα 9, εκεί που κερδίζει τα περισσότερα (σκορ, σύνολα).

Έτσι η αλλαγή αριθμού γίνεται αλλαγή του πίνακα:

```js
const changeCount = (count) => {
  setNames(Array.from({ length: count }, (_, i) => names[i] ?? ''))
}
```

Το `Array.from({ length: 4 }, fn)` φτιάχνει πίνακα 4 θέσεων καλώντας το `fn` για κάθε θέση. Το
`names[i] ?? ''` κρατάει όσα ονόματα έχουν ήδη γραφτεί και βάζει κενό στις νέες θέσεις. Το `??`
σημαίνει «αν είναι `undefined` ή `null`, πάρε το δεξί».

## Controlled text inputs

Όπως το checkbox, έτσι και τα πεδία κειμένου:

```jsx
<input value={name} onChange={(event) => changeName(i, event.target.value)} />
```

Κάθε πλήκτρο καλεί `changeName`, το state αλλάζει, η React ξανασχεδιάζει, και το πεδίο δείχνει τη νέα
τιμή. Ακούγεται πολύ, αλλά είναι γρήγορο, και μας δίνει το κείμενο πάντα έτοιμο στο `names` για
έλεγχο και αποθήκευση.

## Δοκίμασέ το

1. Γράψε ονόματα, πάτα «6» και μετά «3». Τα τρία πρώτα ονόματα μένουν.
2. Βγάλε το `key` από τα κουμπιά και δες την προειδοποίηση στην κονσόλα του browser (F12).
3. Άλλαξε το `changeName` ώστε να κάνει `names[index] = name; setNames(names)`. Γιατί δεν
   δουλεύει πια η πληκτρολόγηση;

## Σύνοψη

- `array.map(item => <Στοιχείο key={…} />)` για λίστες.
- `key`: σταθερό και μοναδικό. Ο δείκτης μόνο για λίστες που αλλάζουν στο τέλος.
- Το state αντικαθίσταται, δεν τροποποιείται: νέοι πίνακες και αντικείμενα.
- Μην αποθηκεύεις ό,τι υπολογίζεται (`names.length`).
