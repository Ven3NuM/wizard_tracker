# Μάθημα 7 · Καθαρές συναρτήσεις και επαναχρησιμοποιήσιμα components

**Στόχοι:** να εκφράσεις τους κανόνες του παιχνιδιού ως καθαρές συναρτήσεις, να φτιάξεις ένα
component που δεν ξέρει τίποτα για το παιχνίδι (`Stepper`), και να ξεχωρίζεις τα components που
«έχουν» δεδομένα από αυτά που απλώς τα δείχνουν.

```bash
npm run lesson 7
```

## Οι κανόνες του γύρου σε μία συνάρτηση

Σε κάθε γύρο χρειαζόμαστε: πόσα φύλλα μοιράζονται, ποιος μοιράζει, ποιος δηλώνει πρώτος. Όλα
βγαίνουν από τρεις αριθμούς: ποιος γύρος, πόσοι παίκτες, ποιος μοίρασε πρώτος.

```js
export const roundInfo = (index, playerCount, firstDealer) => {
  const dealer = (firstDealer + index) % playerCount
  return { index, cards: index + 1, dealer, firstBidder: (dealer + 1) % playerCount }
}
```

- Ο γύρος `index` (από 0) μοιράζει `index + 1` φύλλα.
- Η μοιρασιά προχωράει μία θέση κάθε γύρο. Το `%` (υπόλοιπο) τη γυρίζει πίσω στην αρχή μετά τον
  τελευταίο παίκτη: με 4 παίκτες και πρώτο dealer τη θέση 2, οι dealers είναι 2, 3, 0, 1, 2…
- Πρώτος δηλώνει ο αριστερά του dealer, δηλαδή η επόμενη θέση.

Υπάρχουν και οι πιο απλοί κανόνες `totalRounds` (60 φύλλα / παίκτες) και `sum`.

**Υπολογίζουμε, δεν αποθηκεύουμε.** Το `GameScreen` καλεί `roundInfo(…)` σε κάθε σχεδίαση. Δεν
κρατάμε στο state «ποιος είναι dealer», γιατί προκύπτει πάντα από τα υπόλοιπα. Ο κανόνας του
μαθήματος 4 ξανά.

## Ένα component για όλες τις χρήσεις: `Stepper`

Οι δηλώσεις και οι μπάζες είναι αριθμοί από 0 μέχρι τα φύλλα του γύρου. Στο κινητό, δύο μεγάλα
κουμπιά − και + είναι πολύ πιο βολικά από πληκτρολόγιο. Φτιάχνουμε ένα component γι' αυτό:

```jsx
export default function Stepper({ label, value, max, onChange }) { … }
```

Το `Stepper` **δεν ξέρει τίποτα για το Wizard**: ούτε για δηλώσεις, ούτε για παίκτες. Ξέρει μόνο
«ένας αριθμός από 0 έως `max`». Γι' αυτό θα το χρησιμοποιήσουμε αυτούσιο για δηλώσεις, για μπάζες,
και στο παράθυρο διόρθωσης (μάθημα 11).

Ούτε κρατάει δικό του state: δείχνει το `value` που του δίνεις και σου λέει τη νέα τιμή με
`onChange`. Ένα τέτοιο component λέγεται **controlled**, όπως τα inputs του μαθήματος 3.

Το `label` δεν φαίνεται. Το διαβάζουν οι screen readers («Άννα, Δήλωση: αύξηση»), και θα το
χρησιμοποιήσουν και τα tests του μαθήματος 13 για να βρίσκουν τα κουμπιά.

## Ποιος έχει τα δεδομένα;

```
GameScreen   state: bids          ← «έχει» τα δεδομένα, τα αλλάζει
└── RoundEntry   props: bids, onChange   ← τα δείχνει, ειδοποιεί
    └── Stepper      props: value, onChange   ← το ίδιο, για έναν αριθμό
```

Το `RoundEntry` και το `Stepper` είναι «χαζά» με την καλή έννοια: ό,τι δείχνουν το παίρνουν από
props. Τα καταλαβαίνεις κοιτάζοντας μόνο το αρχείο τους, και τα ξαναχρησιμοποιείς εύκολα. Η λογική
μαζεύεται λίγο πιο πάνω, εδώ στο `GameScreen`.

## Ο κώδικας αυτού του μαθήματος

- **`rules.js`:** προστέθηκαν τα `totalRounds`, `sum`, `roundInfo`.
- **`Stepper.jsx`:** νέο, γενικής χρήσης.
- **`RoundEntry.jsx`:** νέο. Μία γραμμή ανά παίκτη, με badge για dealer και για όποιον δηλώνει πρώτος,
  και σύνολο δηλώσεων πάνω δεξιά.
- **`GameScreen.jsx`:** έχει τις δηλώσεις στο state και δείχνει τον γύρο 1.

Προς το παρόν παίζεται μόνο η δήλωση του πρώτου γύρου. Για μπάζες, επόμενους γύρους και σκορ, το
state γίνεται αρκετά σύνθετο ώστε να αξίζει ένα καινούριο εργαλείο: το `useReducer`, στο επόμενο μάθημα.

## Δοκίμασέ το

1. Διάλεξε διαφορετικό πρώτο dealer στις ρυθμίσεις και δες ποιος παίρνει τα badges.
2. Στο `GameScreen` άλλαξε το `roundInfo(0, …)` σε `roundInfo(3, …)`: τέταρτος γύρος, 4 φύλλα,
   άλλος dealer, χωρίς να αλλάξει τίποτα άλλο.
3. Πάτα «+» μέχρι το τέλος. Γιατί απενεργοποιείται στο 1;

## Σύνοψη

- Οι κανόνες είναι καθαρές συναρτήσεις: ίδια είσοδος, ίδια έξοδος, καμία παρενέργεια.
- Ό,τι υπολογίζεται σε κάθε σχεδίαση δεν μπαίνει στο state.
- Τα καλά components είναι μικρά, με έναν ρόλο, και παίρνουν ό,τι χρειάζονται από props.
