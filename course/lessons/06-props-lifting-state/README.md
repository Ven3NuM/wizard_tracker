# Μάθημα 6 · Props και «ανέβασμα» του state

**Στόχοι:** να περνάς δεδομένα από γονέα σε παιδί με props, να ενημερώνεις τον γονέα με callbacks,
και να αποφασίζεις σε ποιο component «ζει» ένα state.

```bash
npm run lesson 6
```

## Props

Τα components παίρνουν ορίσματα, όπως οι συναρτήσεις. Στη React λέγονται **props** και γράφονται σαν
attributes:

```jsx
<GameScreen game={game} onNewGame={() => setGame(null)} />
```

Το component τα λαμβάνει ως **ένα αντικείμενο**, που συνήθως το «ξεπακετάρουμε» κατευθείαν
(object destructuring):

```jsx
export default function GameScreen({ game, onNewGame }) {
  const { players, hookRule, firstDealer } = game
  …
}
```

Κανόνας: **ένα component δεν αλλάζει ποτέ τα props του.** Είναι δεδομένα που του δόθηκαν, όχι δικά
του. Αν κάτι πρέπει να αλλάξει, το ζητάει από τον ιδιοκτήτη του.

## Τα δεδομένα κατεβαίνουν, τα γεγονότα ανεβαίνουν

```
            App  (state: game)
           /    \
   game ↓ /      \ ↓ onStart
         /        \
  GameScreen      Setup
  ↑ onNewGame     ↑ onStart(setup)
```

- Τα **δεδομένα** περνάνε προς τα κάτω ως props (`game`).
- Το παιδί **ειδοποιεί** τον γονέα καλώντας μια συνάρτηση που του δόθηκε (`onStart`, `onNewGame`).
  Ο γονέας αποφασίζει τι θα γίνει.

Αυτή η μονόδρομη ροή είναι ο λόγος που μια εφαρμογή React μένει κατανοητή καθώς μεγαλώνει: για
κάθε τιμή υπάρχει ένα μέρος όπου αλλάζει. Η σύμβαση ονομάτων για τα callbacks είναι `onΚάτι`.

## Lifting state up

Στο μάθημα 5 το `Setup` κρατούσε μόνο του το «ξεκινήσαμε». Τώρα όμως το παιχνίδι το χρειάζεται και
μια άλλη οθόνη, το `GameScreen`. Δύο αδέλφια δεν βλέπουν το ένα το state του άλλου, άρα:

> Όταν δύο components χρειάζονται το ίδιο state, το μεταφέρουμε στον **πλησιέστερο κοινό γονέα**
> και το δίνουμε και στα δύο με props.

Εδώ ο κοινός γονέας είναι το `App`:

```jsx
const [game, setGame] = useState(null)

{game ? (
  <GameScreen game={game} onNewGame={() => setGame(null)} />
) : (
  <Setup onStart={(setup) => setGame(setup)} />
)}
```

- `game === null` σημαίνει «είμαστε στις ρυθμίσεις».
- Το `Setup` δεν ξέρει τι θα γίνει μετά το «Έναρξη». Απλώς καλεί `onStart({ players, hookRule, firstDealer })`.
- Το `GameScreen` δεν ξέρει πώς ξεκινάει νέο παιχνίδι. Καλεί `onNewGame()` αφού ρωτήσει τον χρήστη.

Το state που αφορά μόνο ένα component μένει σε αυτό: τα ονόματα που πληκτρολογούνται και το μήνυμα
λάθους ζουν ακόμα στο `Setup`. Ανεβάζουμε state μόνο όσο ψηλά χρειάζεται.

## Fragments

Το `GameScreen` επιστρέφει δύο στοιχεία, την κάρτα και τα κουμπιά. Το JSX θέλει ένα στοιχείο στην
κορυφή, οπότε τα τυλίγουμε σε **fragment**, `<>…</>`, που δεν προσθέτει τίποτα στο DOM.

## Ο κώδικας αυτού του μαθήματος

- **`App.jsx`:** έχει το state `game` και αποφασίζει ποια οθόνη φαίνεται.
- **`Setup.jsx`:** το ίδιο με πριν, αλλά αντί για την περίληψη καλεί το `onStart` που του δίνεται.
- **`GameScreen.jsx`:** νέο. Δείχνει τους παίκτες με τη σειρά που κάθονται, σημειώνει τον πρώτο dealer
  με badge, και έχει το «Νέο παιχνίδι» με επιβεβαίωση (`window.confirm`).

## Δοκίμασέ το

1. Ξεκίνα παιχνίδι, πάτα «Νέο παιχνίδι». Τα ονόματα χάθηκαν. Γιατί; (Το `Setup` σβήστηκε από την
   οθόνη, και μαζί του το state του. Στο μάθημα 8 θα το θυμόμαστε.)
2. Πρόσθεσε στο `GameScreen` ένα prop `title` και δείξε το αντί για «Παίκτες».
3. Ζωγράφισε το `GameScreen` δύο φορές μέσα στο `App`. Και τα δύο δείχνουν το ίδιο παιχνίδι, γιατί
   παίρνουν τα ίδια props.

## Σύνοψη

- Props: τα ορίσματα ενός component, μόνο για ανάγνωση.
- Τα δεδομένα κατεβαίνουν με props, τα γεγονότα ανεβαίνουν με callbacks `onΚάτι`.
- Κοινό state → στον πλησιέστερο κοινό γονέα.
- Ένα component που φεύγει από την οθόνη χάνει το state του.
