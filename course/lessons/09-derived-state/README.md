```bash
npm run lesson 9
```

## Το λάθος που κάνουν όλοι

Το πρώτο ένστικτο είναι να κρατάς το σκορ στο state:

```js
game = { …, scores: [50, -10, 20], totals: [120, 30, 80] }
```

Τι γίνεται όταν διορθώσεις τη δήλωση ενός παλιού γύρου (μάθημα 11); Πρέπει να θυμηθείς να
ξαναϋπολογίσεις το σκορ εκείνου του γύρου, **και** τα σύνολα όλων των επόμενων γύρων. Μια ξεχασμένη
γραμμή, και ο πίνακας δείχνει λάθος νούμερα για πάντα.

Η λύση είναι απλή: **το σκορ δεν αποθηκεύεται.** Σε κάθε σχεδίαση υπολογίζεται από τις δηλώσεις και
τις μπάζες, που είναι η μόνη αλήθεια. Αν αλλάξουν, το σκορ είναι αυτόματα σωστό.

```jsx
const table = scoreTable(rounds)   // στο GameScreen, σε κάθε render
```

«Δεν είναι αργό;» Για 20 γύρους × 6 παίκτες είναι 120 προσθέσεις, κάτι που ο browser κάνει σε
μικροδευτερόλεπτα. Κάνε το απλό πρώτα. Αν κάποτε κάτι αργήσει πραγματικά, η React έχει το `useMemo`
για να κρατάει έτοιμους υπολογισμούς, αλλά εδώ δεν χρειάζεται.

## Οι κανόνες βαθμολογίας

```js
export const roundScore = (bid, tricks) =>
  bid === tricks ? 20 + 10 * tricks : -10 * Math.abs(bid - tricks)
```

Ακριβής δήλωση: 20 + 10 ανά μπάζα. Λάθος: −10 για κάθε μπάζα διαφορά.

Ο πίνακας με τα τρέχοντα σύνολα:

```js
export const scoreTable = (rounds) => {
  const table = []
  for (const { bids, tricks } of rounds) {
    const previous = table.at(-1)
    const row = bids.map((bid, p) => {
      const points = roundScore(bid, tricks[p])
      const total = (previous ? previous[p].total : 0) + points
      return { bid, tricks: tricks[p], points, total }
    })
    table.push(row)
  }
  return table
}
```

Για κάθε γύρο φτιάχνουμε μια γραμμή, με ένα κελί ανά παίκτη. Το σύνολο κάθε κελιού είναι το σύνολο του
ίδιου παίκτη στην **προηγούμενη** γραμμή (`previous[p].total`) συν τους πόντους αυτού του γύρου. Στον
πρώτο γύρο δεν υπάρχει προηγούμενη γραμμή, οπότε ξεκινάμε από 0.

«Μα το `push` αλλάζει πίνακα, δεν το αποφεύγαμε;» Το αποφεύγουμε για το **state** (μάθημα 4), γιατί
εκείνον τον πίνακα τον μοιράζεται όλη η εφαρμογή. Το `table` το φτιάχνει η ίδια η συνάρτηση και κανείς
άλλος δεν το έχει δει ακόμα, οπότε το γεμίζουμε όπως θέλουμε. Η συνάρτηση μένει καθαρή: δεν αλλάζει
τίποτα έξω από αυτήν, και ίδιοι γύροι δίνουν πάντα ίδιο πίνακα.

Τα σύνολα είναι η τελευταία γραμμή του πίνακα:

```js
export const totalsOf = (table, playerCount) =>
  table.at(-1)?.map((cell) => cell.total) ?? Array(playerCount).fill(0)
```

Το `at(-1)` δίνει το τελευταίο στοιχείο. Πριν από τον πρώτο γύρο ο πίνακας είναι άδειος, οπότε το
`?.` δίνει `undefined` και το `??` μηδενικά.

## Κατάταξη με ισοβαθμίες

```js
export const ranking = (players, totals) => {
  const sorted = players
    .map((name, seat) => ({ seat, name, total: totals[seat] }))
    .sort((a, b) => b.total - a.total)
  return sorted.map((entry) => ({
    ...entry,
    place: sorted.findIndex((other) => other.total === entry.total) + 1,
  }))
}
```

- Το `sort` με `(a, b) => b.total - a.total` ταξινομεί από τον μεγαλύτερο στον μικρότερο. Το καλούμε
  σε **νέο** πίνακα (αυτόν που έφτιαξε το `map`), όχι σε δεδομένα του state.
- Η θέση κάθε παίκτη είναι η **πρώτη** θέση όπου εμφανίζεται το σκορ του. Δύο παίκτες με 200 είναι και
  οι δύο 1οι, και ο επόμενος είναι 3ος, όπως στον αθλητισμό.
- Κάθε παίκτης κρατάει και το `seat`, τη θέση του στο τραπέζι (0, 1, 2…). Μετά την ταξινόμηση η σειρά
  αλλάζει, και το `seat` είναι αυτό που μας λέει ποιος είναι ποιος: το χρησιμοποιούμε ως `key` στη
  λίστα και για να βρούμε το χρώμα του παίκτη. Το όνομα είναι για να το **δείχνουμε**, όχι για να
  **αναγνωρίζουμε** κάποιον. Αν κάποτε επιτρέπαμε δύο «Γιώργους», όλα θα δούλευαν ακόμα.

## Ο κώδικας αυτού του μαθήματος

- **`rules.js`:** προστέθηκαν τα `roundScore`, `scoreTable`, `totalsOf`, `ranking`.
- **`Scoreboard.jsx`:** νέο. Πίνακας με έναν γύρο ανά γραμμή. Σε κάθε κελί, πάνω το σύνολο και κάτω
  «δήλωση/μπάζες ±πόντοι», πράσινο ή κόκκινο. Στην κορυφή τα σύνολα, με τον πρώτο τονισμένο. Η
  τελευταία γραμμή δείχνει τον τρέχοντα γύρο.
- **`FinalResults.jsx`:** νέο. Η κατάταξη στο τέλος.
- **`reducer.js`:** νέο action `REMATCH`: ίδιοι παίκτες, ο πρώτος dealer μετακινείται μία θέση.
- **`GameScreen.jsx`:** υπολογίζει τον `table` μία φορά και τον δίνει και στα δύο components που τον
  χρειάζονται.

Για προσβασιμότητα, οι επικεφαλίδες του πίνακα έχουν `scope="col"`, και το «#» έχει
`aria-label="Γύρος"`, για να διαβάζεται κάτι πιο κατανοητό από «δίεση».

## Σύνοψη

- Αν μπορεί να υπολογιστεί από το state, υπολόγισέ το σε κάθε render. Μην το αποθηκεύεις.
- Οι μετατροπές δεδομένων (`map`, `reduce`, `sort`, `findIndex`) ζουν σε καθαρές συναρτήσεις.
- Υπολόγισε μία φορά ψηλά (`table`) και δώσε το με props σε όποιον το χρειάζεται.
