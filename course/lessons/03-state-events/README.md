# Μάθημα 3 · State και events

**Στόχοι:** να αντιδράς σε κλικ, να κρατάς τιμές που αλλάζουν με το `useState`, και να καταλάβεις
γιατί μια απλή μεταβλητή δεν φτάνει.

> **Πριν ξεκινήσεις**
>
> - **State:** η «μνήμη» ενός component: τιμές που αλλάζουν όσο τρέχει η εφαρμογή (πόσοι παίκτες, αν είναι ενεργός ο κανόνας). Όταν αλλάζει, η React ξανασχεδιάζει την οθόνη μόνη της.
> - **Event:** κάτι που έκανε ο χρήστης: κλικ, πληκτρολόγηση. Στη React το «πιάνεις» με `onClick`, `onChange`.
> - **Hook:** οι συναρτήσεις της React που ξεκινούν από `use` (εδώ το `useState`). Δίνουν σε ένα component δυνατότητες όπως μνήμη.
> - **Arrow function:** η σύντομη γραφή συνάρτησης `() => …`, που θα βλέπεις σε κάθε event.
>
> Όλοι οι όροι μαζεμένοι: [Λεξικό](../../GLOSSARY.md).

## Events

Στη σκέτη JavaScript γράφεις `button.addEventListener('click', …)`. Στη React δίνεις τη συνάρτηση
απευθείας στο JSX:

```jsx
<button onClick={() => setPlayerCount(4)}>4</button>
```

Το `() => setPlayerCount(4)` είναι μια **arrow function**, μια πιο σύντομη γραφή συνάρτησης:

```js
function () { return setPlayerCount(4) }   // η παλιά γραφή
() => setPlayerCount(4)                    // το ίδιο, ως arrow function
(event) => setHookRule(event.target.checked)   // με παράμετρο
(a, b) => {                                // με πολλές γραμμές: άγκιστρα και return
  const total = a + b
  return total
}
```

Όταν το σώμα είναι μία έκφραση, χωρίς άγκιστρα, η τιμή της επιστρέφεται αυτόματα. Θα τις βλέπεις
παντού στη React, γιατί δίνουμε συνεχώς μικρές συναρτήσεις σε events και σε `map`.

Προσοχή: δίνεις **μια συνάρτηση** για να κληθεί αργότερα, όχι το αποτέλεσμα της κλήσης.

```jsx
onClick={() => setPlayerCount(4)}   // σωστό: καλείται όταν γίνει το κλικ
onClick={setPlayerCount(4)}         // λάθος: καλείται αμέσως, σε κάθε σχεδίαση
```

Τα events που θα χρησιμοποιήσουμε: `onClick`, `onChange` (inputs), `onSubmit` (forms, μάθημα 5).
Η συνάρτηση παίρνει ένα αντικείμενο `event`, π.χ. `event.target.checked` για ένα checkbox.

## Γιατί όχι μια απλή μεταβλητή;

```jsx
function Setup() {
  let playerCount = 3
  return <button onClick={() => { playerCount = 4 }}>…</button>
}
```

Αυτό **δεν** δουλεύει, για δύο λόγους:

1. Η αλλαγή μιας μεταβλητής δεν λέει στη React να ξανασχεδιάσει την οθόνη.
2. Ακόμα κι αν ξανασχεδιαζόταν, το `Setup()` θα ξανατρέχε από την αρχή και το `let playerCount = 3`
   θα το έκανε πάλι 3. Οι τοπικές μεταβλητές δεν «θυμούνται» ανάμεσα στις σχεδιάσεις.

## `useState`

```jsx
import { useState } from 'react'

const [playerCount, setPlayerCount] = useState(3)
```

- Το `useState(3)` λέει: «θέλω μια τιμή που να τη θυμάσαι εσύ, η React, με αρχική τιμή 3».
- Επιστρέφει δύο πράγματα: την **τωρινή τιμή** και μια **συνάρτηση για να την αλλάξεις**.
- Το `const [a, b] = …` λέγεται array destructuring: παίρνει τα δύο στοιχεία με τη σειρά.
- Η σύμβαση ονομάτων είναι `κάτι` / `setΚάτι`.

Όταν καλείς `setPlayerCount(4)`:

1. η React αποθηκεύει το 4,
2. **ξανατρέχει τη συνάρτηση `Setup`** (λέγεται re-render),
3. αυτή τη φορά το `useState` επιστρέφει 4,
4. η React συγκρίνει το νέο JSX με το προηγούμενο και αλλάζει στο DOM μόνο ό,τι διαφέρει.

Αυτό είναι το «οθόνη = f(δεδομένα)» του μαθήματος 1 στην πράξη: δεν γράφουμε πουθενά «κάνε το
κουμπί 4 πράσινο». Γράφουμε `aria-pressed={playerCount === 4}` και η React κρατάει την οθόνη
συγχρονισμένη.

### Οι κανόνες των hooks

Οι συναρτήσεις που ξεκινούν με `use` λέγονται **hooks**. Δύο κανόνες:

- Τα καλείς **μόνο στην κορυφή** ενός component, όχι μέσα σε `if`, `for` ή εσωτερικές συναρτήσεις.
- Τα καλείς **μόνο μέσα σε components** (ή σε δικά σου hooks, μάθημα 10).

Η React αναγνωρίζει ποιο state είναι ποιο από τη **σειρά** των κλήσεων, γι' αυτό η σειρά πρέπει να
είναι ίδια σε κάθε σχεδίαση. Το ESLint του project σε προειδοποιεί αν παραβείς τους κανόνες.

## Controlled inputs

Το checkbox του κανόνα hook είναι **controlled**: την τιμή του την ορίζει το state, και κάθε αλλαγή
περνάει από το state.

```jsx
<input
  type="checkbox"
  checked={hookRule}
  onChange={(event) => setHookRule(event.target.checked)}
/>
```

Έτσι υπάρχει **μία πηγή αλήθειας**: το `hookRule`. Το DOM απλώς το δείχνει. Αν ξεχάσεις το
`onChange`, το checkbox «κολλάει», γιατί η React το επαναφέρει στην τιμή του state.

## Ο κώδικας αυτού του μαθήματος

- Το `playerCount` κρατάει τον επιλεγμένο αριθμό. Κάθε κουμπί κάνει `setPlayerCount(n)` και είναι
  πατημένο όταν `playerCount === n`.
- Το `hookRule` είναι controlled checkbox.
- Η γραμμή «3 παίκτες, χωρίς κανόνα hook» υπάρχει μόνο για να βλέπεις το state να αλλάζει. Χρησιμοποιεί
  τον τελεστή `συνθήκη ? α : β` μέσα στο JSX.

Δύο πράγματα «ενοχλούν» ακόμα, και είναι σκόπιμα:

- Τα τέσσερα κουμπιά είναι σχεδόν ίδιος κώδικας τέσσερις φορές.
- Τα πεδία ονομάτων μένουν τρία, ό,τι κι αν διαλέξεις.

Και τα δύο λύνονται στο επόμενο μάθημα με λίστες.

## Σύνοψη

- Events: `onClick={() => …}`, δίνεις συνάρτηση, δεν την καλείς.
- `useState` = τιμή που η React θυμάται. Το `set…` την αλλάζει και ξανασχεδιάζει το component.
- Hooks μόνο στην κορυφή των components.
- Controlled input: το state ορίζει την τιμή, το `onChange` την αλλάζει.
